# Состояние работы с локальным Docker Registry

## 1. Этап, на котором остановились

Остановились на втором этапе — переводе сборок и проверок на локальный registry. Образы скопированы, digest `uv` совпал. Осталось выполнить pull всех рабочих ссылок, сборку и проверки на VM. К третьему этапу не переходили. Сетевое ограничение registry решено настроить позже.

## 2. Изменения

- Добавили отдельный Compose-файл для registry с постоянным томом.
- Привязали registry к `192.168.56.111:5000`.
- Описали запуск registry и наполнение образами в README.
- Перевели базовые образы сборок на локальный registry.
- Перевели образы Gitleaks, Python и Trivy для проверок на локальный registry.
- Закрепили версии и digest образов.
- Обновили статическую проверку Dockerfile и её тест.
- Исправили ссылки для Skopeo: источник теперь задаётся по digest без тега.

## 3. Выполненные действия и команды

Ниже сначала идут фактически выполненные действия. Невыполненные проверки вынесены отдельно в конце.

**Создали рабочую ветку от `dev`:**

```bash
git switch -c codex/local-docker-registry
```

**Проверили, что порт 5000 на Ubuntu VM свободен:**

```bash
ss -tlnp
```

**Проверили конфигурацию registry Compose на VM:**

```bash
docker compose -f docker-compose.registry.yml config --quiet
```

**Скачали образ registry и запустили контейнер на VM:**

```bash
docker compose -f docker-compose.registry.yml pull
docker compose -f docker-compose.registry.yml up -d
```

**Проверили состояние, журнал, порт и HTTP-ответ registry на VM:**

```bash
docker compose -f docker-compose.registry.yml ps
docker compose -f docker-compose.registry.yml logs --tail=100 registry
ss -tlnp | grep ':5000'
curl -v --max-time 5 http://192.168.56.111:5000/v2/
ip -br addr
```

Контейнер работал, HTTP-запрос вернул `200 OK` и `{}`.

**Проверили доступ к registry с Windows в PowerShell:**

```powershell
Test-NetConnection 192.168.56.111 -Port 5000
curl.exe -v --max-time 5 http://192.168.56.111:5000/v2/
```

TCP-подключение прошло, HTTP-запрос вернул `200 OK` и `{}`.

**Добавили HTTP registry в настройки Docker daemon на VM:**

```bash
sudo tee /etc/docker/daemon.json >/dev/null <<'EOF'
{
  "insecure-registries": ["192.168.56.111:5000"]
}
EOF
sudo dockerd --validate --config-file /etc/docker/daemon.json
sudo systemctl restart docker
```

Проверка конфигурации вернула `configuration OK`.

**Отправили тестовый образ в registry, скачали его и повторили pull после перезапуска:**

```bash
docker compose -f docker-compose.registry.yml up -d
docker tag registry:2.8.3@sha256:a3d8aaa63ed8681a604f1dea0aa03f100d5895b6a58ace528858a7b332415373 \
  192.168.56.111:5000/registry-check:2.8.3
docker push 192.168.56.111:5000/registry-check:2.8.3
docker pull 192.168.56.111:5000/registry-check:2.8.3
docker compose -f docker-compose.registry.yml restart
docker pull 192.168.56.111:5000/registry-check:2.8.3
```

Digest до и после перезапуска совпал.

**Добавили registry в Docker Desktop на Windows:**

```json
{
  "insecure-registries": ["192.168.56.111:5000"]
}
```

Настройка внесена через **Docker Desktop → Settings → Docker Engine → Apply & restart**.

**Проверили настройку Docker Desktop в PowerShell:**

```powershell
docker info
docker info --format '{{json .RegistryConfig.IndexConfigs}}'
```

Для `192.168.56.111:5000` отображалось `"Secure": false`.

**Отключили containerd image store в Docker Desktop после ошибки HTTP pull:**

```text
Docker Desktop → Settings → General
→ снять Use containerd for pulling and storing images
→ Apply & restart
```

**Повторили pull тестового образа в PowerShell:**

```powershell
docker pull 192.168.56.111:5000/registry-check:2.8.3
```

Все пять слоёв скачались, digest совпал с опубликованным на VM.

**Установили Skopeo на Ubuntu VM:**

```bash
sudo apt-get update
sudo apt-get install skopeo
```

**Скопировали многоплатформенные образы в локальный registry с повторными запусками после сбоев сети:**

```bash
registry_copy_status=0
while read -r source destination; do
  skopeo copy --all --preserve-digests --dest-tls-verify=false \
    "docker://$source" "docker://192.168.56.111:5000/$destination" ||
    { registry_copy_status=1; break; }
done <<'EOF'
docker.io/library/registry@sha256:a3d8aaa63ed8681a604f1dea0aa03f100d5895b6a58ace528858a7b332415373 library/registry:2.8.3
ghcr.io/astral-sh/uv@sha256:f459f6f73a8c4ef5d69f4e6fbbdb8af751d6fa40ec34b39a1ab469acd6e289b7 astral-sh/uv:0.9.5
registry.access.redhat.com/ubi9/python-312@sha256:19e1e927138b40454858f297884c2c4e2f13f5ba95b3f55faea174d3cbb57067 ubi9/python-312:1
docker.io/nginxinc/nginx-unprivileged@sha256:5aea7cc516b419e3526f47dd1531be31a56a046cfe44754d94f9383e13e2ee99 nginxinc/nginx-unprivileged:1.29.3-alpine
docker.io/library/postgres@sha256:665dc7b37ac52a17e298511414c21d23ffa4e6a6ef6225b3e5d59c7afb35e994 library/postgres:17.11-bookworm
docker.io/library/python@sha256:f3fa41d74a768c2fce8016b98c191ae8c1bacd8f1152870a3f9f87d350920b7c library/python:3.12.12-slim
docker.io/zricethezav/gitleaks@sha256:b5918eb91b8d2473cec722f066abb4352e4ffdc4ec9f4283ec143aba9ec9ebc4 zricethezav/gitleaks:v8.24.2
docker.io/aquasec/trivy@sha256:029e990b328d149bf0a9ffe355919041e1f86192db2df47e217f8a36dd42ceac aquasec/trivy:0.59.1
EOF
test "$registry_copy_status" -eq 0 && echo "Копирование завершено"
```

Последний запуск вывел `Копирование завершено`.

**Сравнили исходный и локальный digest `uv` на VM:**

```bash
(
  set -o pipefail
  skopeo inspect --raw \
    docker://ghcr.io/astral-sh/uv@sha256:f459f6f73a8c4ef5d69f4e6fbbdb8af751d6fa40ec34b39a1ab469acd6e289b7 |
    sha256sum
  skopeo inspect --tls-verify=false --raw \
    docker://192.168.56.111:5000/astral-sh/uv:0.9.5 |
    sha256sum
)
```

Оба результата совпали: `f459f6f7…`.

**Локально проверили Docker-конфигурации и тесты:**

