# Первый запуск

Приложение целиком работает в Docker: PostgreSQL, миграции, API и Frontend.
Внешняя БД не используется. Внешний файл настроек поддерживается через
ENV_FILE без встроенного пути; автоматически системный файл не ищется. Создаётся новая пустая БД; старые данные не переносятся.

На Windows используйте [инструкцию без Make](DOCKER_WINDOWS.md).

На Linux установите Docker Engine с Compose и GNU Make, затем откройте терминал
в корне проекта. Сначала выполните только команду ввода:

~~~bash
read -r -s -p 'Путь к env-файлу (вставьте его после приглашения): ' ENV_FILE; printf '\n'
~~~

После запуска терминал ждёт ввод: вставьте путь к файлу и нажмите Enter.
`-p` — это только текст приглашения; путь вводится после него, не между
кавычками команды. Затем выполните:

~~~bash
if [ -n "$ENV_FILE" ] && [ -r "$ENV_FILE" ]; then
  export ENV_FILE
  echo 'ENV_FILE задан, файл доступен для чтения.'
  make setup
  make run
else
  echo 'ENV_FILE пуст или файл недоступен. Повторите ввод.' >&2
fi
~~~

В этом же терминале рабочие команды `make status`, `make migrate` и другие
унаследуют `ENV_FILE`. В новом терминале введите путь снова. Для локального
`.env`/значений по умолчанию выполните `unset ENV_FILE`.
Windows-инструкция без Make: [DOCKER_WINDOWS.md](DOCKER_WINDOWS.md).

Интерфейс: http://localhost:5180. Создайте первого администратора.
API: http://localhost:8010/docs. Проверка БД: http://localhost:8010/health/ready.
API запускается только после успешного Alembic upgrade head.

~~~bash
make status
make down
~~~

Down сохраняет данные. Повторный make run использует тот же том.
Настройки можно задать во внешнем файле ENV_FILE или корневом .env
по .env.example; файлы с реальными реквизитами не коммитятся.
Реквизиты по умолчанию демонстрационные, порты привязаны к loopback.
Не публикуйте этот учебный HTTP-стенд в сеть как production.

Автотесты: make test; полная проверка: make verify.
Проверки используют отдельную контейнерную БД и не очищают БД приложения.
Подробности: [GUIDE.md](../GUIDE.md).

Внешние настройки задаются через ENV_FILE: [правила передачи и изоляция тестов](../GUIDE.md#внешний-файл-настроек).
Make и deploy учитывают переменную автоматически. В прямых рабочих командах
Compose добавляйте `--env-file "$ENV_FILE"` (Linux) или
`--env-file "$env:ENV_FILE"` (PowerShell), если переменная задана.

[Миграции, backup/restore и ограничения ресурсов](DATABASE_OPERATIONS.md) — команды для Make, Linux и PowerShell.
