# Скрипт запуска Compose

deploy/deploy.sh теперь является оболочкой Docker Compose. Он больше не
устанавливает Python/Node, не создаёт системных пользователей/службы, не
клонирует ветки, не настраивает UFW и не подключает внешнюю БД.

Из корня на Linux с установленным Docker:

~~~bash
sh deploy/deploy.sh --validate-only
sh deploy/deploy.sh
~~~

Первая команда проверяет Compose-конфигурацию, вторая собирает и запускает
весь стек с ожиданием готовности. Используется docker-compose.yaml.
Настройки — во внешнем файле ENV_FILE либо в корневом .env по .env.example;
deploy/.env больше не читается.
DEPLOY_ROLE, REPOSITORY_URL и прежние параметры systemd не поддерживаются.

Миграции запускаются автоматически, ошибка препятствует старту API.
Наличие контейнера не заменяет проверку readiness и пользовательского сценария.
Backup, восстановление, обновление и откат описаны в [GUIDE.md](../GUIDE.md).
Проверка оболочки без Docker-операций: sh deploy/test_deploy.sh.

Внешние настройки задаются через ENV_FILE: [правила передачи и изоляция тестов](../GUIDE.md#внешний-файл-настроек).
Make и deploy учитывают переменную автоматически. В прямых рабочих командах
Compose добавляйте `--env-file "$ENV_FILE"` (Linux) или
`--env-file "$env:ENV_FILE"` (PowerShell), если переменная задана.

Обёртка Compose требует Python 3.11+ для проверки каталогов, запускается от
обычного оператора и выставляет LOCAL_UID/LOCAL_GID; root-контейнеры запрещены.
Подробнее: [политика контейнеров](CONTAINER_POLICY.md).
