# Повторяемое развёртывание без Docker

Статус: номер задачи отсутствует. Скрипт автоматизирует установку зависимостей,
получение ветки `main`, сборку, миграции, systemd и UFW на Ubuntu. Он не
устанавливает PostgreSQL и не изменяет `postgresql.conf` или `pg_hba.conf`.

## Задача и критерии приёмки

Цель — повторить развёртывание без ручного создания пользователей, окружений,
unit-файлов и правил UFW. Границы задачи: Ubuntu с systemd, один сервер
приложения и отдельный либо локальный PostgreSQL; установка самой БД, backup,
Nginx, TLS и откат схемы не входят в скрипт.

Критерии приёмки: первый запуск создаёт требуемое окружение и запускает обе
службы; повторный запуск пропускает актуальные шаги; локальные Git-изменения не
перезаписываются; frontend доступен только указанной клиентской сети, а порт БД
на сервере с ролью `db` — только серверу приложения. Проверка выполняется через
синтаксический анализ Bash, повторный запуск на тестовых Ubuntu-серверах,
health-маршруты и просмотр `systemctl status`/`ufw status`.

Скрипт влияет на схему данных только при запуске Alembic. Перед рабочей
миграцией требуется отдельная проверенная резервная копия; бизнес-данные и
существующие Git-изменения скрипт не удаляет.

## Подготовка

Скопируйте каталог `deploy/` на целевой сервер. Рядом с `deploy.sh` создайте
локальный файл `.env`:

```bash
cd deploy
cp .env.example .env
chmod 600 .env
editor .env
```

Обязательно замените `REPOSITORY_URL`, `DATABASE_URL`, `SSH_NETWORK`,
`CLIENT_NETWORK` и адреса серверов. Файл `.env` игнорируется Git. Скрипт читает
только известные параметры в формате `ИМЯ=ЗНАЧЕНИЕ` и не выполняет содержимое
файла как shell-код.

Для приватного репозитория заранее настройте deploy key и `known_hosts` для
пользователя службы в каталоге `SERVICE_HOME`. Не помещайте токен в
`REPOSITORY_URL`: Git сохранит такой URL в `.git/config`.

Перед включением UFW убедитесь, что `SSH_NETWORK` содержит адрес вашей
административной сети. Желательно оставить вторую SSH-сессию открытой или
иметь доступ к консоли сервера.

Проверить заполнение файла без изменений системы можно командой:

```bash
./deploy.sh --validate-only
```

## Сервер приложения

В `.env` установите `DEPLOY_ROLE=app`, затем запустите:

```bash
chmod +x deploy.sh
sudo ./deploy.sh
```

Скрипт последовательно проверит и при необходимости:

1. установит Git, curl, UFW, Python 3.11, Node.js и закреплённую версию pnpm;
2. создаст непривилегированного пользователя;
3. клонирует репозиторий или безопасно обновит `main` только fast-forward;
4. создаст `venv`, установит зависимости и соберёт frontend;
5. перенесёт runtime-настройки в `/etc`, создаст три unit-файла и применит миграции;
6. включит firewall, автозапуск backend/frontend и выполнит health-проверки.

Если Python 3.11 отсутствует в доступных пакетах Ubuntu, скрипт подключает PPA
deadsnakes. Для установки системного Node.js используется официальный DEB-репозиторий
[NodeSource](https://github.com/nodesource/distributions). Эти внешние
репозитории требуют сетевого доступа и должны быть разрешены политикой вашей
организации.

Если в существующем репозитории есть незакоммиченные изменения или `origin`
не совпадает с `REPOSITORY_URL`, скрипт остановится и ничего не перезапишет.
То же произойдёт, если локальная ветка содержит commits, отсутствующие в
`origin/main`: скрипт не выполняет reset и не переписывает историю.

## Сервер PostgreSQL

Скопируйте те же два файла на сервер БД, задайте `DEPLOY_ROLE=db`,
`APP_SERVER_IP` и `SSH_NETWORK`, затем снова выполните:

```bash
sudo ./deploy.sh
```

В этом режиме скрипт не устанавливает приложение. Он разрешает TCP-порт
PostgreSQL только с `APP_SERVER_IP`, сохраняет несвязанные правила UFW и
включает политику `deny incoming`. Если уже существует более широкое
разрешение для порта БД, скрипт остановится и попросит удалить его вручную.
Отдельно настройте PostgreSQL по инструкции
[Firewall для API и PostgreSQL](FIREWALL.md): `listen_addresses` и
`pg_hba.conf` должны подтверждать то же ограничение.

## Повторный запуск

Скрипт можно запускать повторно. Он сверяет версии программ, commit ветки,
контрольные суммы зависимостей и содержимое конфигурации/unit-файлов. Уже
выполненные шаги отмечаются в выводе и пропускаются. Службы перезапускаются
только после относящихся к ним изменений.

Миграции применяются только если `alembic current` не сообщает актуальную
ревизию. Для рабочей БД перед миграциями требуется проверенная резервная копия;
автоматическое создание backup в этот скрипт не входит.

## Откат

Скрипт не выполняет автоматический откат. Верните Git к заранее проверенной
ревизии отдельным контролируемым действием и повторите развёртывание. Откат
кода допустим только при совместимой схеме БД; восстановление или downgrade БД
выполняются по отдельному утверждённому плану.
