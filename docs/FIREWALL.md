# Сеть контейнерного приложения

Все зависимости находятся в сети выбранного Compose-проекта. PostgreSQL
доступен сервисам как db:5432; порт БД на Windows/Linux-хост не публикуется.
Не требуется настраивать внешний PostgreSQL, pg_hba.conf или сервер БД.

| Контур | API хоста | Frontend хоста | БД |
| --- | --- | --- | --- |
| Приложение | 127.0.0.1:8010 | 127.0.0.1:5180 | Только сеть Compose |
| Make-проверки | 127.0.0.1:8001 | 127.0.0.1:5174 | Отдельная сеть и том |
| Linux test-runner | Не публикуется | Не публикуется | Отдельная сеть и том |

Порты приложения меняются APP_PORT/FRONTEND_PORT; тестовые —
TEST_API_PORT/TEST_FRONTEND_PORT. Прокси Frontend идёт на app:8000.
Не открывайте 5432 наружу ради браузера: браузер обращается только к API.

Локальный режим development использует HTTP и cookie без Secure.
Публикация в сеть требует отдельной настройки TLS, cookie и ограничений доступа.
Не отключайте защиту Host в Vite для обхода ошибки неизвестного имени;
проверяйте UI по http://localhost:5180.

Проверки:

~~~text
docker compose -f docker-compose.yaml ps -a
docker compose -f docker-compose.yaml logs --tail 100 db migrate app frontend
~~~

Разделение Compose-проектов не заменяет полноценную изоляцию Docker Engine.
Не передавайте рабочие секреты или внешний Docker socket непроверенным тестам.

Внешние настройки задаются через ENV_FILE: [правила передачи и изоляция тестов](../GUIDE.md#внешний-файл-настроек).
Make и deploy учитывают переменную автоматически. В прямых рабочих командах
Compose добавляйте `--env-file "$ENV_FILE"` (Linux) или
`--env-file "$env:ENV_FILE"` (PowerShell), если переменная задана.
