## Запуск

- make test — Backend и Frontend через основной тестовый Compose.
- make migration-check — миграции.
- make backup-restore-check — реальное восстановление в тестовом контуре.
- make mutation — мутационные проверки.
- make quality — статические и security-проверки.
- make container-smoke — контейнерный сценарий и Trivy.
- make verify — обязательный полный контур.
- [Отдельный Linux-образ](UNIX_TESTS.md) — Backend, Frontend, сборка и миграции.

Команды требуют подготовленного окружения и отдельных тестовых ресурсов.
container-smoke получает image ID непосредственно из запущенного контейнера.

## Неполнота покрытия

Существующие проверки не закрывают всю матрицу TASK.md. В частности:
отказ commit и rollback истории, гонки проведения с PATCH/архивированием,
согласованность нескольких SQL-запросов отчёта, сумма 0.1+0.2 одного
материала, разные единицы, выгрузка больше страницы, все роли и ошибки новых
экранов, обновление кешей после проведения. В миграционном upgrade-сценарии
данные справочников до обновления не заменяют проверку всех старых документов.

Frontend coverage и браузерные E2E не настроены. Успешная сборка не
подтверждает поведение интерфейса. Smoke не проводит поступление и не
проверяет отчёт. Очередь, outbox и worker исключены из согласованного MVP;
синхронное проведение и отчёты уже реализованы и тестируются.

Конфигурация внешнего ENV_FILE: tests/unit/test_compose_configuration.py
проверяет рабочие Make-команды, пробелы/спецсимволы, пустую переменную, отказ
для неверного пути и изоляцию test-clean. deploy/test_deploy.sh проверяет обе
команды deploy и сохранение пути одним аргументом.

Регрессии мутационного запуска: tests/unit/test_critical_mutations.py.
Проверяются выполнение изменённой копии, отказ при выжившей мутации, отказ
при ошибке исходного теста и обнаружение импорта из исходного каталога.

Жизненный цикл API: tests/unit/test_application_lifecycle.py проверяет lifespan,
освобождение пула и фабрики сессий, а в Linux — настоящий SIGTERM во время
HTTP-запроса к Uvicorn с проверкой завершения запроса и shutdown.

Backup: tests/unit/test_backup_publication.py проверяет уникальность имён при
одинаковой временной метке и отсутствие опубликованного дампа при сбое pg_dump.
backup_restore_check.sh дополнительно проверяет отказ для повреждённого дампа
и существующей цели без разрешения.
