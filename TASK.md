# ТЗ: миграция frontend на нативные HTML, JavaScript и CSS

Исполнитель: ИИ-агент 6.0 Luna. Полностью заменяет прежний TASK.md.
Задача без номера. Реализовать миграцию, а не только описать план.

## 1. Процесс и принятые решения

Прочитать AGENTS.md, README.md, актуальные исходники/тесты и близкие инструкции.
Проверить Git, сохранить чужие изменения. Создать ветку frontend/native-js-migration
от текущего состояния; если она уже существует, проверить её назначение и состояние,
не сбрасывать и не перезаписывать её. Имя ветки прямо задано пользователем и имеет
приоритет над общим префиксом codex/. Не выполнять commit/push и не создавать PR.

Приложение — только статические HTML/CSS/JS, нативные ES modules и Web APIs.
Полностью удалить React, JSX/TSX, TypeScript, React Router, TanStack Query,
React Hook Form, Zod, Lucide и остальные runtime frontend-зависимости.
Удалить Vite, React-плагин, Vitest, jsdom, Testing Library, Prettier и TypeScript
инструменты; сторонние frontend dev-пакеты допустимы только для ESLint.
SAST и поиск секретов сохраняются как внешние инструменты существующего контура.
Не заменять библиотеки CDN-загрузкой, vendoring или другим фреймворком.
Backend и его зависимости не подпадают под запрет frontend-библиотек.

Для тестов использовать встроенные node:test, node:assert, mock и coverage Node.js;
сторонние тестовые пакеты и браузерные automation-зависимости не добавлять.
Node/pnpm остаются инструментами контейнеров проверки, а не runtime frontend.

## 2. Неизменность поведения

Сначала составить в рабочем анализе перечень всех существующих страниц, действий,
состояний и тестовых сценариев; не создавать для этого отдельный документ.
Сохранить для пользователя весь существующий функционал и максимально внешний вид:
вход/выход/первичная регистрация, профиль, роли, обзор, справочники единиц/материалов/
поставщиков, поиск/пагинация/архивирование, поступления/позиции/проведение/история,
отчёты/фильтры/CSV, администрирование в пределах фактически реализованных функций,
404, модальные окна, ошибки, загрузку/пустые состояния, подтверждения действий.
Не добавлять несуществующий функционал и не заменять готовую страницу заглушкой.
Сохранить ограничения проведённых документов, точность количеств и правила форм.

Повторно использовать текущий CSS, адаптивность, семантический HTML, подписи,
фокус/клавиатуру и доступность. Иконки заменить локальными SVG без библиотеки,
с корректными aria-hidden/accessible names. Не загружать внешние шрифты/иконки
как новую скрытую зависимость. Не выполнять редизайн.

## 3. Нативная архитектура

Сохранить SPA и текущие пути /login, /units, /materials, /suppliers, /receipts,
/reports, /admin, /profile и остальные существующие пути. Использовать History API,
popstate, корректную обработку back/forward, прямого открытия и refresh URL.
Не перехватывать внешние ссылки, download, modifier-click и target=_blank.

Выделить небольшие ES modules для API, маршрутизации, состояния сеанса, общих DOM
элементов и страниц. Не писать собственные React/virtual DOM, универсальный
framework компонентов, event bus или DI-контейнер. KISS и DRY важнее имитации
удалённых библиотек. Обеспечить снятие listeners, отмену запросов при переходах,
отсутствие повторных обработчиков и защиту от устаревших async-ответов.
Не выполнять сетевые запросы/DOM-монтаж при импорте тестируемой чистой логики.

Запросы — fetch и AbortController, существующие JSON/API-контракты и относительные
URL. Сохранить cookies credentials, CSRF, X-Request-ID, server error/request_id,
204, JSON/non-JSON ошибки, CSV и обработку 401. Токены не переносить в localStorage.
Сохранить существующие гарантии актуальности данных после мутаций; не воспроизводить
весь Query framework. Изменяющие запросы автоматически не повторять.

Валидация — HTML constraints и простые JS-функции с прежними правилами/сообщениями;
backend остаётся источником авторизации и бизнес-ограничений. Не подставлять
недоверенные строки в innerHTML/insertAdjacentHTML, event attributes или JS URLs:
использовать textContent, DOM API и проверку URL. Статические шаблоны без данных
допустимы при ясной границе. Не маскировать XSS SAST-исключениями.

## 4. Статическая доставка и Docker

Предпочтительная минимальная схема: существующий non-root Nginx напрямую отдаёт
frontend HTML/CSS/JS и проксирует /api и /health двум backend. Vite runtime и
отдельный Node frontend-сервис удалить; не оставлять фиктивный frontend-контейнер.
Можно собрать собственную Nginx-цель Dockerfile со статикой и nginx-конфигурацией.
Сохранить порт 8080, non-root, backend balancing/retry/instance header, БД/тома.
Backend API/миграции не менять ради UI-миграции.

Настроить History fallback только для маршрутов страниц. Отсутствующий .js/.css/
.svg должен давать 404, а не HTML; /api и /health не попадать в SPA fallback.
Проверить MIME модулей, относительные импорты и адреса ресурсов при вложенном URL.
Не кешировать index.html так, чтобы он ссылался на устаревшие модули; не задавать
immutable для нефингерпринтованных файлов. Отдельный сборщик для статики не нужен.
Удалить HMR/WebSocket прокси, VITE_* и старые проверки Node frontend health.

Адаптировать Dockerfile, Compose, .dockerignore и тестовые Docker-файлы, Makefile
setup/build/up/status/diagnostics/container-check, security image targets к реальному
новому составу сервисов. Рабочий runtime не содержит Node/npm/pnpm/node_modules.
Не уменьшать охват image/security проверок молча: frontend теперь часть образа
Nginx, проверяется этот образ; backend и db сохраняются. Не создавать фиктивный
успешный scan несуществующего frontend-образа. README описывает новую схему.
Секреты .env не читать/не менять/не копировать; испытания — изолированный проект.
Docker разрешён для этих испытаний, рабочие данные/контейнеры не трогать.

## 5. Тесты и честное изменение метрик

Перенести имеющиеся полезные сценарии с React/Vitest на node:test, не удаляя
проверки поведения без замены. Тестировать чистую логику API/фильтров/валидации/
маршрутов/обработки ошибок и состояния с контролируемыми fetch/history подменами.
Не писать собственный jsdom и не выдавать примитивные DOM-моки за браузерный тест.
DOM-поведение проверить в настоящем браузере имеющимися средствами среды либо
вручную; новые Playwright/Selenium и прочие тестовые библиотеки не добавлять.

node:test не предоставляет DOM и независимую statements-метрику, поэтому прежнюю
четырёхметричную Vitest-проверку нельзя объявлять эквивалентной. После выбора
пользователем встроенного runner установить обязательные 40% для lines, branches,
functions и целевой ориентир 60%. Statements отметить как недоступную метрику,
не вычислять её приблизительно и не подменять lines. Backend 80% сохранить.

Считать весь прикладной JS, а не только импортированные тестом модули. Проверить
фактическое поведение Node coverage include на неимпортированных файлах выбранной
версии. Если runner не включает их, добавить минимальный безопасный discovery
coverage-модулей без DOM side effects либо другой честный учёт отсутствующих файлов
без сторонних инструментов; нельзя исключить страницы ради процента.
Любые неохваченные браузерные сценарии явно перечислить, не объявлять автоматическую
приёмку интерфейса по одним unit-тестам.

Вывод node:test — терминал и встроенный JUnit, coverage — текст/LCOV по возможностям
закреплённой Node-версии. Отчёты только reports/<run-id>/frontend, сохраняются после
cleanup. Не писать собственный HTML/Cobertura generator ради прежнего формата,
не обещать отчёты, которых встроенный инструмент не создаёт.
Не передавать shell glob с разным поведением Linux/Windows без проверки обнаружения.

## 6. Качество и контур проверок

make test сохраняет backend и запускает нативные frontend-тесты в контейнере.
make quality сохраняет backend-проверки, frontend ESLint и SAST; удалить frontend
Prettier/TypeScript/Vitest вызовы, а не оставлять их как echo success. ESLint
проверяет новый JS с --max-warnings=0. SAST правила адаптировать к vanilla DOM,
проверить опасные/безопасные fixtures; поиск секретов сохранить.
make verify остаётся последовательным с корректными статусами и кодами выхода.

В frontend/package.json оставить type: module, необходимые scripts и только
линтерные devDependencies; runtime dependencies пусты/отсутствуют. pnpm-lock
перегенерировать штатно pnpm@11.19.0, frozen-install должен проходить. Удалить
ненужный undici override, React/TS/Vite конфиги и пакеты, не удаляя backend lock.
Аудит оставшихся lint-зависимостей сохраняется. Исправить пути SAST JS/fixtures,
security_policy и сводки отчётов без ослабления их политики.

## 7. Приёмка

Проверить:
- зависимости/исходники/HTML не содержат React, JSX/TS, библиотечного runtime,
  Vite и внешних CDN-загрузок; frontend-образ заменён статической доставкой;
- pnpm frozen-install, ESLint и SAST проходят, negative fixtures обнаруживаются;
- native tests и три coverage thresholds >=40%, цель 60%, полный охват JS честный;
- UI в настоящем браузере: все страницы, регистрация/вход/выход, профиль,
  справочники CRUD/архив, поступления/подтверждение/история, отчёты/CSV,
  роли/401/CSRF/ошибки, модальные окна/клавиатура/адаптивность;
- direct URL/refresh/back/forward, query string, 404 assets/MIME, неизвестный route;
- две backend-реплики работают через порт 8080, X-Instance-ID сохраняется,
  static delivery не ломает API, одиночный отказ backend проверяется изолированно;
- make build/test/quality/verify/security/container-check в доступной среде,
  сохранение отчётов и точечная очистка только тестовых ресурсов;
- git diff --check и связанные команды README обновлены и реально проверены.

Не утверждать прохождение браузерной проверки, Docker или CI без запуска.
При недоступной среде выполнить независимые изменения/проверки и перечислить
оставшуюся приёмку. Не завершать реализацию после одной заготовки или аудита.

## 8. Границы и результат

Разрешены необходимые новые JS-модули, HTML/CSS/SVG, замена тестов и удаление
заменённых React/TS-файлов, изменения manifest/lock, Docker/Compose/Nginx,
Makefile/scripts проверок, конфигурации ESLint/SAST и существующего README.
Не создавать дополнительные инструкции, отчёты вне reports и посторонние файлы.
Реализация должна сохранять функции, а не просто визуально похожую стартовую страницу.

Комментарии/docstring — на русском, идентификаторы — на английском.
Строго придерживаться Keep It Simple, Stupid! (KISS), Don't Repeat Yourself (DRY),
SOLID без лишних абстракций. Не ослаблять backend-проверки и security-политику.

Итог: изменённые критические файлы, перечень сохранённых сценариев, реальные команды,
результаты/покрытие и границы сопоставимости метрик, визуальная приёмка/пропуски,
риски. Данные и миграции не меняются. Откат — возврат совместимого frontend/Nginx
и сборочных конфигураций без удаления БД. Не выполнять deploy без поручения.
